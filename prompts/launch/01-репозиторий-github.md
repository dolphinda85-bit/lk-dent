# Заливаем проект в приватный репозиторий GitHub

## Зачем

Репозиторий - это «облачная копилка» вашего проекта с историей всех изменений. GitHub - сайт, где эти копилки хранятся. Пока проект живёт только на вашем компьютере, любой сбой диска = потеря всей работы. Как только он в репозитории, у вас есть:

- резервная копия «в облаке»;
- история версий - можно вернуться к тому, что работало вчера, если сегодня что-то сломали;
- одинаковый проект на всех устройствах и на сервере.

Ключевое слово - **приватный** (private). Приватный репозиторий видите только вы и те, кого вы позвали. Публичный видит весь интернет. Для рабочего проекта по умолчанию берём приватный.

## Когда применять

- Начали новый проект и хотите с самого старта хранить его безопасно.
- Дописали заметный кусок работы и хотите зафиксировать его как «точку сохранения».
- Собираетесь потом выкладывать проект в интернет (см. `02-деплой.md`) - сначала он должен быть в репозитории.

## Текст запроса к агенту

Скопируйте, при необходимости подставьте своё название проекта:

```
Помоги залить мой проект в НОВЫЙ ПРИВАТНЫЙ репозиторий на GitHub. Я не программист, объясняй по-русски и по шагам.

1. Сначала проверь, что в проекте нет секретов, которые нельзя выкладывать: файлы вроде .env, ключи, пароли, токены, данные пациентов. Если такие есть - добавь их в файл .gitignore, чтобы они НЕ попали в репозиторий, и покажи мне список того, что исключил.
2. Сделай первый коммит (сохранение всего проекта в историю) с понятным сообщением.
3. Помоги создать на GitHub НОВЫЙ приватный репозиторий и отправить туда проект.
4. В конце покажи, что именно уехало на GitHub, и подтверди, что ни один секрет туда не попал.

Перед каждым необратимым действием останавливайся и объясняй простыми словами, что оно делает.
```

Отдельно полезно один раз потренировать откат - чтобы не бояться экспериментировать:

```
Покажи на моём проекте, как вернуться к предыдущей сохранённой версии (к прошлому коммиту), а потом как вернуться обратно к текущей. Сделай это безопасно, без потери работы, и объясни каждый шаг простыми словами. Это тренировка, я хочу понять механику отката.
```

## Что делать с результатом

- Зайдите на github.com в свой репозиторий и глазами убедитесь: файлы на месте, замок «private» стоит.
- Возьмите за привычку делать коммит после каждого заметного шага. Коммит - это ваша кнопка «сохранить». Чем чаще жмёте, тем меньше теряете.
- Потренированный откат - ваша страховка. Теперь можно смелее пробовать: сломали - откатились.

## Предупреждения о безопасности

- **Секреты в репозиторий не кладём. Никогда.** Пароли, ключи доступа, токены, содержимое `.env`, реальные данные пациентов. Если такое хоть раз уехало на GitHub - считайте, что ключ утёк, даже после удаления файла (он остаётся в истории). Правильно - сразу сменить этот ключ на новый.
- **Только приватный репозиторий.** Публичный видит весь интернет, включая поисковики и ботов, которые специально ищут чужие ключи.
- Секретам место в переменных окружения или в защищённом хранилище (Keychain на Маке, настройки сервера), а не в файлах проекта.
- Данные пациентов (152-ФЗ) в маркетинговый/учебный проект вообще не попадают - им место только в защищённом РФ-контуре.
- Если агент предлагает сделать репозиторий публичным «для удобства» - не соглашайтесь без явной причины.
